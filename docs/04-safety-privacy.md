# 医疗安全、隐私与滥用防护

## 1. 安全目标

本系统定位为“健康膳食信息与计划辅助工具”，不是医疗器械，不诊断疾病，不替代医生或注册营养师，不建议停药、换药或调整治疗方案。安全控制必须位于 LLM 之前和之后：输入先分级，检索前施加禁忌过滤，输出后校验风险提示和引用，不能只依赖提示词中的一句免责声明。

## 2. 风险分级与响应策略

| 等级 | 典型情况 | 系统动作 | 是否生成个性化热量/营养素目标 |
|---|---|---|---|
| S0 普通 | 健康成年人、一般食材或方案查询 | 正常检索、推荐并引用 | 可以，且必须展示假设和来源 |
| S1 谨慎 | 过敏/不耐受、素食、痛风、乳糖不耐、麸质相关限制 | 强制排除冲突项，提示复核配料和个体差异 | 仅在资料支持范围内给一般建议 |
| S2 限制 | 已确诊糖尿病、肾病、心血管疾病、孕期/哺乳期、未成年人、进食障碍史 | 不给治疗性或精确处方；仅提供 A/B 中的一般原则和就医提示 | 禁止自动生成精确处方 |
| S3 紧急 | 晕厥、胸痛、严重低血糖表现、呼吸困难、严重过敏等 | 中止普通问答，建议立即联系当地急救或线下医疗机构 | 禁止 |

说明：资料 A 的适用人群范围有限。年龄、疾病或生理状态超出资料覆盖时，系统应明确说明证据边界，不得靠模型常识补全为个体医疗意见。

## 3. 确定性安全门

后端 `SafetyService` 在模型调用前执行以下检查，并返回结构化结果：

```json
{
  "risk_level": "S0|S1|S2|S3",
  "matched_rules": ["allergy_shellfish"],
  "blocked_food_tags": ["shellfish"],
  "allow_personalized_targets": true,
  "required_notice": "general|professional|emergency"
}
```

规则至少覆盖：食物过敏、乳糖不耐、麸质/乳糜泻、痛风、肾病、糖尿病、高血压、心血管疾病、孕期、哺乳期、未成年人、进食障碍、极端减重、药物调整和紧急症状。健康档案中的禁忌标签必须参与候选召回前过滤；模型不得“看到后自行决定是否遵守”。

## 4. 输出安全校验

生成后的 `AnswerValidator` 必须检查：

1. 每个营养数字、方案名和禁忌结论均有 A/B 引用；
2. 平台类事实只引用 C，C 不得支持营养建议；
3. S2/S3 响应未出现个体化处方、确诊、疗效保证或药物调整；
4. 过敏或禁忌食材没有出现在推荐候选中；
5. 必需的专业提示存在且位于答案主体附近；
6. 没有“百分百有效”“治愈”“替代就医”等绝对化表述。

校验失败时最多重生成一次；仍失败则返回安全降级模板、现有引用和可追问项，并记录 `request_id`，不能把未经校验的内容展示给用户。

## 5. 提示注入与知识污染防护

- 上传资料不在比赛 P0 范围内；生产知识源仅接受 manifest 白名单中的固定文件与版本。
- 检索片段被标记为“不可信数据”，片段中的指令不得改变系统规则。
- 路由与 `source_role` 过滤由后端代码执行，LLM 不能覆盖。
- 引用只允许指向数据库中已登记的 `chunk_id`，拒绝模型虚构 URL、页码或文档名。
- 用户输入限制长度和频率；HTML/Markdown 输出先净化，外部链接默认不激活。
- 管理端导入需要单独权限、文件类型检查、大小限制、哈希记录和人工验收。

## 6. 数据最小化与用户权利

健康目标、禁忌和对话属于敏感数据。P0 默认支持匿名会话，不要求真实姓名；注册账号只收集邮箱和认证所需字段。系统不收集身份证、精确住址或支付信息。所有日志避免写入完整健康档案和原始对话，诊断日志使用 request ID、规则标签和脱敏摘要。

当前实现与发布要求：

- 本地开发使用 HTTP；公网生产必须使用 HTTPS，托管 PostgreSQL 应启用 TLS。ACTION-05 关闭前不得宣称公网传输门已完成；
- 密码使用 scrypt 加盐哈希，认证令牌服务端仅存 SHA-256 哈希并在 30 天后失效；
- 当前 Web 使用 `localStorage` bearer token，服务端集中执行鉴权和资源归属检查。HttpOnly/Secure/SameSite Cookie 与 CSRF 防护是正式长期运营前的加固项，不写成当前能力；
- 用户可删除单条会话、导出账号数据并以密码确认永久删除账号；删除覆盖同一组个人数据表；
- 当前没有自动对话保留 worker，对话保存至用户删除、账号删除或比赛运营方清理；该限制在 `PRIVACY.md` 明确披露；
- 健康档案为请求内临时状态，不单独落库；聊天正文中的健康信息仍随对话持久化；
- 真实密钥只通过本地 `.env` 或部署平台 Secret 注入；提交候选扫描不得命中真实 Secret；
- 错误消息和结构化日志不返回原始健康文本、密码、令牌、堆栈、SQL、模型密钥或内部 Prompt。

机器可读数据路径见 `docs/release-data-map.json`，面向用户的实际说明见根目录 `PRIVACY.md`。任何数据类别、Provider、SDK 或部署接收方变化都必须同时更新三处并重跑 P08-03 文档门。

## 7. 安全验收门禁

安全测试集至少包含：

- 6 类食物过敏/禁忌，每类 2 条；
- 糖尿病、肾病、痛风、高血压、孕期/哺乳期各 2 条；
- 4 条极端减重或进食障碍倾向；
- 4 条药物/治疗替代请求；
- 4 条紧急症状；
- 8 条提示注入、越权与知识串库；
- 4 条删除/导出/跨用户访问。

上线硬门槛：高风险识别召回率 100%，禁忌食材误推荐 0，A/B/C 串库 0，跨用户数据访问 0，真实 Secret 扫描命中 0。任何一项失败都阻止发布。
