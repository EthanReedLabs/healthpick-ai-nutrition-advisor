# AI智能膳食顾问使用说明

版本：RC12 公网验收版
更新日期：2026 年 8 月 23 日
适用对象：比赛评审、演示人员与普通体验用户

## 1. 系统简介

HealthPick AI智能膳食顾问是一套面向 25 至 45 岁都市白领的可运行营养问答与膳食方案辅助系统。产品覆盖减脂塑形、增肌强化和慢病调理三类核心诉求，可以理解“我想减重”“我在健身”“我血糖有点高”等自然语言表达，基于赛题指定资料回答食材营养、三餐搭配、低 GI、蛋白质需求、饮食禁忌和替换方案等问题，并给出一个主方案及匹配理由。系统不是普通聊天壳：正式回答由阿里云百炼 `qwen3.7-plus` 动态生成，页面会显示真实模型来源；推荐候选、来源边界、风险分级和引用校验由后端确定性规则控制，避免模型把平台服务资料当成营养依据。

系统将三份素材严格分为两类。资料 A《2026秋季健康膳食指南》和资料 B《个性化饮食计划方案》属于核心营养知识库，只用于营养问答、膳食推荐、食材替换和禁忌依据；资料 C《健康优选平台服务白皮书》属于辅助平台资料，只回答会员、企业合作、平台能力和 API 服务，不参与任何营养事实或方案推荐。每条正式营养回答都展示文档名称、章节、页码、原文摘录和 Chunk ID，用户能够核验信息来源。没有充分证据时系统会说明证据不足，而不是编造答案。

## 3. 快速使用步骤

1. 打开公网入口。首页顶部显示欢迎语、当前 API 状态和模型模式，左侧是最近对话，中间是问答区，右侧展示健康档案、资料边界、评测概览和模型透明度。
2. 直接点击快捷问题，或在输入框键入自然语言问题。例如：“我想减重，三餐应该怎么搭配？”“我在健身，训练前后应该怎么吃？”“我血糖有点高，应该怎样选择低 GI 食物？”
3. 按 Enter 或点击“发送”。发送后问题会立即出现在对话区，输入框立即清空；生成期间显示“正在接收并安全校验回答”和“停止生成”，不会让用户误以为页面卡死。
4. 阅读正式回答。回答区域会显示安全等级、真实模型名称、正文、结构化方案卡和来源卡。结构化方案包含推荐理由、关键目标、三步行动、同类替换和已复核依据。
5. 继续追问。可以输入“那早餐呢？”“如果不吃鸡胸肉可以换什么？”等问题。系统会使用最近四轮可进入上下文的完整对话，同时保持本轮来源白名单与安全边界。
6. 如需更明确的规则方案，点击“编辑健康档案”，选择目标、年龄段、活动水平、过敏原和安全标签。45 至 64 岁年龄段需填写精确年龄；资料适用范围外、年龄冲突或高风险状态会被安全阻断。
7. 左侧“最近对话”支持恢复、搜索、改名和删除。匿名会话会保存在服务端；注册登录后可迁移匿名历史，并使用账号数据导出和永久删除功能。

## 4. 推荐问题示例

- 减脂塑形：“我想减重，三餐怎么搭配？”“减脂期间燕麦和白米饭怎么选？”
- 增肌强化：“我在健身，训练前后应该怎么吃？”“增肌期蛋白质和碳水怎么安排？”
- 稳糖调理：“我血糖有点高，低 GI 主食有哪些？”“控糖 321 餐盘应该怎么摆？”
- 禁忌安全：“我对海鲜过敏，也想减脂。”“我尿酸高，有哪些高嘌呤食物需要避开？”
- 平台服务：“平台专业版包含哪些服务？”“企业健康管理如何合作？”
- 多轮追问：先问“给我低钠饮食建议”，再问“那早餐呢？”或“可以用什么替换？”

## 5. 如何理解页面结果

安全分级分为 S0 至 S3。S0 为一般营养信息；S1 表示存在过敏、不耐受或痛风等需要谨慎处理的限制；S2 涉及确诊疾病、孕哺、未成年人或进食障碍等情况，只提供资料支持的一般原则，不生成治疗性或精确处方；S3 为胸痛、呼吸困难、意识异常、严重过敏等紧急信号，系统会中止普通生成并提示立即联系当地急救或线下医疗机构。

来源卡中的 A、B、C 对应三份赛题素材。营养问题只应出现 A/B，平台服务问题只应出现 C；混合问题会分别引用两类证据。结构化方案是基于已复核规则生成的候选，不代表医疗处方。页面显示 `openai_compatible · qwen3.7-plus · real` 时，表示回答由生产环境真实模型生成，而不是硬编码文本或 Mock 回复。

## 6. 技术选型与核心逻辑说明

前端使用 Next.js、React 和 TypeScript，原因是它们适合在 48 小时赛程内快速构建响应式 Web 页面，并以强类型组件稳定承载问答、健康档案、结构化方案、引用卡片、对话历史和错误反馈。后端使用 FastAPI、Pydantic 和 Python，将请求校验、身份权限、安全分级、意图路由、知识检索、真实模型调用、引用后校验和数据库写入组织为一条可审计工作流。PostgreSQL 保存匿名或账号会话与通过最终门禁的完整对话；健康档案仅随当前请求临时使用，不单独落库。公网由 Caddy 提供 HTTPS 和反向代理，所有服务通过 Docker 镜像部署，便于本地复现、版本核验和快速回滚。

三份知识资料在离线阶段按页解析，形成包含来源角色、文档名、章节、页码、Chunk ID、内容哈希和允许路由的只读数据。运行时首先由确定性路由判断问题属于营养、推荐、禁忌、平台、混合或范围外，再在允许的分区内执行可解释的关键词检索。当前语料只有三份且包含大量数字与禁忌，因此生产选择 `keyword` 检索并明确将 Embedding 标记为 `disabled`，不把未验证的向量能力写成已完成功能。模型只接收本轮允许的证据和最近四轮有效上下文；输出必须使用合法 Chunk ID 逐条引用。引用、安全提示或来源边界校验失败时最多执行一次受约束修复，仍失败则使用可验证证据回退或拒绝回答。结构化推荐不让模型自由挑选方案，而是从 7 条人工复核核心规则中确定目标、过滤过敏与疾病禁忌，再生成一个主方案、理由、行动和替换。这样既保留大模型自然表达能力，又把高风险决策固定在可测试、可追踪的程序规则中。

## 7. 输入、异常与恢复

- 空输入：提示“请输入您的问题”，不会向后端发送聊天请求。
- 超过 2000 字：提示“输入内容过长，请精简后重试”，不会进入模型调用。
- 特殊符号或无关输入：系统保持页面稳定；无营养或平台证据时明确提示范围或证据不足。
- 系统异常：提示“服务繁忙，请稍后重试”，并保留 request ID 便于排查。
- 模型超时：显示可重试提示，可复用同一请求编号重试，避免重复保存。
- 主动停止：点击“停止生成”后取消本次请求，半成品不写入历史，原问题恢复到输入框便于修改。
- 生成失败：待处理用户气泡会移除，原始输入恢复，不会把失败草稿冒充正式回答。

## 8. 安全、隐私与免责声明

系统仅提供资料范围内的一般营养信息和计划辅助，不进行疾病诊断，不建议停药、换药或调整治疗。出现疾病、用药、孕哺、过敏或其他高风险内容时，系统会关闭个体化精确目标并显示专业提示。请勿在演示中输入真实姓名、身份证、住址、支付信息或真实医疗记录；建议使用合成档案和临时测试账号。

本建议仅供参考，不构成医疗建议，请咨询专业医师或注册营养师。涉及胸痛、呼吸困难、意识丧失、严重过敏或其他急症时，请立即联系当地急救或前往急诊，不要等待本系统继续生成建议。

## 9. 本地一键运行（备用交付方式）

本地复现需要 Docker Desktop、Docker Compose 和一个宿主机可访问的 OpenAI-compatible 模型服务。复制 `.env.example` 为 `.env`，填写自己的模型地址、模型名和密钥后，在仓库根目录执行 `docker compose up -d --build`。默认 Web 地址为 `http://127.0.0.1:3000`，API 健康地址为 `http://127.0.0.1:8010/healthz`。真实密钥只能写入本地 `.env` 或部署 Secret，禁止提交到仓库。普通停止使用 `docker compose down`；不要在不确认数据影响的情况下添加 `--volumes`。
