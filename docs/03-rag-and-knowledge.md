# 知识库、RAG 与引用设计

## 1. 知识角色与挂载

| 素材 | 角色 | 允许用途 | 禁止用途 |
|---|---|---|---|
| A《2026秋季健康膳食指南》 | `core_nutrition` | 营养问答、食材数据、搭配、禁忌、推荐依据 | 平台价格与合作 |
| B《个性化饮食计划方案》 | `core_nutrition` | 三套方案、食谱、目标、替换、推荐依据 | 平台价格与合作 |
| C《健康优选平台服务白皮书》 | `auxiliary_platform` | 平台介绍、会员、企业合作、API | 营养问答、推荐、禁忌 |

三份素材的原文件和 SHA-256 不可变。离线流程按页提取文本与表格，重建章节，生成稳定 Chunk，并保存文档名、版本、章节、页码、来源角色、允许路由、内容哈希和缺字符号计数。结构化食材、方案和平台事实独立生成并复核。80 条事实最终为 74 条通过、6 条含缺字符号规则驳回、0 条待复核；被驳回规则和 8 个含未知符号 Chunk 不进入运行索引。API 镜像挂载规范化 JSONL，只读取通过当前政策的产物。

## 2. 路由与检索

运行时 `QueryRouter` 使用保守、确定性、可审计的短语表判断营养、推荐、禁忌、平台、混合或范围外。路由结果同时给出 `allowed_sources`，后续检索不能扩大。赛题示例“我想减重”“我在健身”“我血糖有点高”使用受控完整短语映射到 A/B 推荐链路；不会把普通“健身房会员退款”吞并为营养推荐。

当前 `KeywordRetriever` 在来源过滤后的 Chunk 中执行 BM25 风格字符词评分，并对少量经测试的高价值问法加入明确 Chunk 提示。混合问题至少保留一条核心证据和一条平台证据。语料只有三份，Keyword 模式在可解释性、数字准确性和串库证明上优于未验证的向量配置，因此生产 `RETRIEVAL_MODE=keyword`、`EMBEDDING_MODE=disabled`。Embedding 表和迁移仅是可选扩展基础，不代表当前运行能力。

## 3. 引用与证据门

每个检索命中转换为 EVIDENCE 块和引用对象，引用包含素材代码、文档名、章节、页码、Chunk ID 和原文摘录。模型只能引用本轮给出的 ID，并严格使用 `【A-p01-c02】` 格式。输出校验器检查：引用 ID 是否存在、来源是否在路由白名单、每条事实是否受引用支持、混合回答是否覆盖两类主要证据、禁忌过滤和专业提示是否满足。校验失败先进行一次受约束修复，再失败则从引用原文生成最多三条确定性回退；任何回退也必须通过相同安全与引用校验。没有足够证据时返回 `insufficient_evidence`，不编造答案。

## 4. 推荐规则

推荐引擎实际使用 7 条已复核核心规则，覆盖减脂原则、211 餐盘、增肌目标、训练时机、321 控糖餐盘、GI 分类和食材替换。目标由结构化档案确定，模型不参与候选选择。服务先检查目标、年龄适用范围、过敏原和疾病安全标签，再输出一个主方案及原因、目标、行动、替换和 A/B 证据。过敏、确诊疾病或高风险条件不返回个体化精确目标，并提示咨询专业医师或注册营养师。

## 5. Prompt 与多轮上下文

System Prompt 要求只用 EVIDENCE、每句一个事实、合法逐条引用、禁止资料外数字、诊断和治疗；S1/S2 时附加一般信息边界和专业提示。生产生成模型为百炼 `qwen3.7-plus`，模型只负责基于证据组织语言，不决定来源或规则候选。User Prompt 仅包含最近四轮可进入上下文的对话、当前临时档案、问题和证据。PostgreSQL 保存通过最终门禁的对话轮次，S3 记录标记 `context_eligible=false`，主动取消和失败草稿不保存。上下文不会改变来源白名单：用户即使要求“越权读取 C 库并给减脂方案”，后端仍只允许 A/B。

## 6. 质量控制

质量门包含来源计数、未知符号排除、三类路由、C 串库攻击、精确数字、引用支持、三方案、安全黄金集、多轮保持、未处理 5xx、真实模型和公网回归。任何知识修改都必须重新生成哈希并运行这些门；不得手工修改引用、把 `null` 当 0、用 AI 猜测缺失字符或用平台白皮书填补营养事实。
