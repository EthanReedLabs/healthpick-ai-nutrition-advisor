# P04-02 确定性推荐候选设计与验收

## 已实现

- 推荐候选只读取 `knowledge/normalized/facts/plan_rules.jsonl` 中的 A/B 规则；C 无法进入目录。
- 规则必须同时满足：`review_status=verified`、不存在未知缺字符号、具有 `second_person_review` 记录。
- 目标、年龄范围和安全分级在候选生成前判定；S1/S2/S3 均不返回个体化目标。
- 目标到方案的映射、匹配分、关键目标、三步行动、同类替换和依据均由确定性代码生成，LLM 不参与候选选择。
- 最多返回一个主方案和一个备选；当前实现返回一个主方案，备选为空。
- 真实目录尚未完成 ACTION-06，因此本地 API 正确返回 `blocked` 和三条待复核规则，不展示占位方案。

## 验收覆盖

1. 真实目录未复核规则全部被排除；
2. 缺目标、年龄范围不明确、过敏和肾病均 fail-closed；
3. 合成的已复核目录覆盖减脂、增肌和稳糖三类主方案；
4. 轻盈减脂合成案例产生 95 分规则匹配、3 条行动、A/B 依据和同类替换；
5. 未知缺字符号或缺第二人复核记录的规则不能进入候选池；
6. 真实 API 与 375px 浏览器均显示明确复核门禁。

## 残余行动

ACTION-06 完成后，应由复核流程把确认无误的规则置为 `verified` 并写入 `second_person_review`；届时同一代码路径会自动放行主方案。不得为了演示手工绕过该门禁。
