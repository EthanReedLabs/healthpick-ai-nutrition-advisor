# P06-04 用户数据导出与删除验收

结论：`PASS`。账号导出、个人数据计数和永久删除覆盖同一个数据面，删除前要求重新验证密码，静态知识资料明确排除且删除后保持不变。

## 实现与安全边界

- `GET /v1/account/export` 导出当前账号、登录会话元数据、账号会话、对话和轮次；令牌哈希、密码哈希、数据库连接与静态知识内容不导出。
- `DELETE /v1/account` 要求 Bearer 身份和当前密码；PostgreSQL 在单一事务中验证密码并删除用户，既有外键级联清除全部个人表。
- Ephemeral 与 PostgreSQL 实现使用相同导出/删除契约；Web 下载结构化 JSON，并以不可撤销提示、密码二次输入和独立危险操作区降低误删。
- 删除成功后浏览器清除本地令牌与账号邮箱，创建新的匿名会话和空对话，不复用已删除 ID。

## 实施中发现并解决

- ISSUE-055：API 身份辅助函数返回 UUID，而存储接口按字符串用户 ID 匹配，首个导出用例误报 401；API 边界统一规范字符串后全部通过。
- ISSUE-056：删除确认表单只有密码字段，浏览器给出密码管理器/可访问性提示；增加隐藏用户名语义后干净浏览器会话提示消失。

## 采用的工程经验

采用 Sulde `tech-docs/个人数据计数导出删除必须覆盖同一数据面`：同一验收同时核对导出清单、计数总和、删除后个人表归零与静态知识保留，避免“能导不能删”或“删不干净”。
