# AI 辅助开发使用披露

## 披露结论

本参赛项目使用 OpenAI Codex 辅助赛题分析、代码实现、测试生成、失败诊断、评测脚本、文档和项目治理；参赛者负责范围确认、资料核对、安全边界、外部授权、验收与最终提交。产品公网运行时使用阿里云百炼北京地域 Token Plan 的 `qwen3.7-plus` 动态生成回答，`LLM_MODE=real`；当前 `RETRIEVAL_MODE=keyword`，`EMBEDDING_MODE=disabled`。本地 Compose 可选择 Ollama 作为复现用兼容 Provider，但本地模型结果不冒充公网百炼结果。

AI 输出从未被当作营养事实真源。营养知识和推荐依据只能来自素材 A《2026秋季健康膳食指南》与素材 B《个性化饮食计划方案》；素材 C《健康优选平台服务白皮书》只用于平台、会员和企业合作问题。结构化事实的最终处置、缺字符号排除、核心规则放行、引用校验和医疗安全门均由确定性程序及人工复核共同约束。

## 人工优化的核心理由

健康营养场景同时包含数字、禁忌、疾病和隐私风险，语言模型擅长组织表达却不适合独立决定事实、来源范围或医疗边界。因此人工优化集中在四处：第一，把素材 A/B 与 C 的用途固化为检索前过滤；第二，把推荐候选限定为已逐条复核的规则，模型只解释；第三，在模型前后都执行安全和引用校验，失败时拒答或证据回退；第四，用真实浏览器、PostgreSQL、百炼和公网 HTTPS 复验生成代码。这样既使用 AI 提高 48 小时开发效率，又保留可追溯、可证伪的工程责任链。

## 使用信息与未交给 AI 的事项

- AI 工具：OpenAI Codex；具体协作模型版本由 Codex 宿主配置决定，未作为产品运行模型宣传。
- 使用日期：2026-08-21 至 2026-08-23。
- 生产模型：阿里云百炼 `qwen3.7-plus`，页面透明度接口和回答元数据如实标注。
- 检索：确定性路由 + KeywordRetriever；Embedding 未启用。
- 人工复核：ACTION-06 已关闭，74 条通过、6 条驳回、0 条待处理；推荐实际使用 7 条核心规则。
- 未交给 AI：编造或补写资料、决定医疗诊断/用药、放宽过敏和疾病限制、处理真实密钥、改变服务器/DNS、支付、比赛账号提交及最终法律或资格判断。

AI 不承担最终事实正确性、医疗安全、隐私合规、许可证判断或比赛资格责任；这些责任由参赛团队承担。
