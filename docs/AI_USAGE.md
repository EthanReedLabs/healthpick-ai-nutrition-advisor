# AI 辅助开发使用披露

## 披露结论

本项目使用 OpenAI Codex 作为代码、测试、评测、文档和项目治理协作工具；产品运行时使用本地 `qwen2.5:3b-instruct` 生成回答、`qwen3-embedding:0.6b` 完成 Embedding 验证。AI 输出没有被视为事实真源，营养知识仍以赛题资料 A/B、平台事实以资料 C、发布状态以控制面证据为准。

## 使用实录

| 模块 | AI 辅助内容 | 人工责任与关键修改 | 证据/状态 |
|---|---|---|---|
| 赛题分析与架构 | 需求拆分、追踪矩阵、RAG/安全/部署方案草案 | Project Lead 冻结代码优先路线、P0/P1 和外部授权边界 | Phase 01 记录已接受 |
| 知识生产 | 辅助编写确定性页级解析、Chunk、Schema、事实生成和隔离检查代码 | 原文与哈希为真源；缺字符号保持排除；第二人逐条事实复核仍由团队完成 | ACTION-06 开放，不伪报完成 |
| API/RAG/安全 | 辅助实现 Provider、检索、引用、账号、会话、安全门、取消和错误合同 | 通过人工设定的来源/医疗规则、单测、真实模型和 PostgreSQL 复验 | Python 254 项通过 |
| Web/体验 | 辅助实现响应式聊天、引用、档案、历史、透明评测、数据导出删除和停止生成 | 人工浏览器核对桌面/移动、可访问名称、焦点、无溢出和真实数据流 | Web 30 项及浏览器证据通过 |
| 评测 | 辅助构建 72 cases / 80 turns 数据与 runner、分析失败 | 阈值先冻结；原失败不覆盖；6 个错误断言以原文/安全策略形成显式 v1.1 勘误 | 九项发布门通过 |
| DevOps/安全 | 辅助实现 Compose、迁移/seed、故障切换、密钥与依赖审计 | 实际运行 Docker/Ollama/PostgreSQL；真实 Secret 不进入仓库；公网部署仍需用户授权 | P08-01/02 本地证据通过 |
| 文档与治理 | 辅助维护逐任务记录、问题日志、控制板、隐私/许可证/提交说明 | Project Lead 逐项接受任务记录；最终 P08-07 重新审计，不由 AI 自行签署 | 结构审计 PASS，最终 NOT_READY |

## 使用信息

- AI 工具：OpenAI Codex（本地工作区协作；具体托管模型版本由 Codex 会话配置决定）。
- 使用日期：2026-08-21 至 2026-08-22。
- 主要任务类型：赛题分析、代码实现、单元/API/E2E 用例、失败诊断、评测与证据整理、技术文档。
- 采用的输出：经测试或原文证据验证的代码、测试、结构化文档和实施记录。
- 重大人工/确定性修改：A/B/C 硬隔离、安全阈值、事实勘误、禁忌过滤、外部授权边界和最终接受状态均由确定性规则或 Project Lead 决定。
- 最终审核责任：Project Lead；结构化事实的第二人复核由 KNOWLEDGE/LEAD 负责，ACTION-06 关闭前不签署最终知识准确性。
- 验证方式：254 项 Python、30 项 Web、真实 72/80 评测、真实 PostgreSQL/Ollama、浏览器与 Compose 生命周期、密钥/依赖审计。

## 明确未交给 AI 的事项

- 不让 AI 编造、补写或“合理推断”资料缺失字符和营养数字。
- 不用 AI judge 替代来源泄漏、数字、医疗、安全、多轮和 5xx 的确定性发布门。
- 不用硬编码回答或 mock 结果冒充真实模型演示。
- 不让 AI 自动决定付费、区域、公网发布、七天在线责任或最终提交签署。
- 不把 AI 生成文字表述为未经人工核验的原创医学事实。

AI 不承担最终事实正确性、医疗安全、隐私合规、许可证判断或比赛资格责任；这些责任由参赛团队承担。
