# 演示脚本与提交清单

## 1. 六分钟演示脚本

| 时间 | 演示内容 | 证明点 |
|---:|---|---|
| 0:00–0:30 | 一句话痛点、目标用户和产品首页 | 场景理解、产品完成度 |
| 0:30–1:20 | 普通用户提出目标，系统追问并生成 1–2 个方案 | 动态 LLM、澄清、推荐逻辑 |
| 1:20–2:00 | 展开答案引用，显示 A/B 文档、章节、页码和证据 | RAG、可追溯、非硬编码 |
| 2:00–2:50 | 补充“海鲜过敏/不吃某食材”，修改同一方案 | 多轮记忆、禁忌硬过滤 |
| 2:50–3:30 | 提出肾病或孕期精确处方请求 | 风险分级、安全拒答、专业提示 |
| 3:30–4:10 | 询问平台套餐，再问混合问题 | C 单独路由、A/B/C 0 串库 |
| 4:10–4:50 | 切换历史会话、刷新后恢复、展示手机视口 | 持久化、用户体验、响应式 |
| 4:50–5:30 | 打开透明评测页与架构图 | 指标、测试、工程可信度 |
| 5:30–6:00 | 展示公网 URL、Compose 启动方式和价值总结 | 可部署、可复现、交付完整 |

演示输入写入固定脚本，但回答必须来自真实运行链路。演示账号预置非敏感样例画像；现场不使用参赛者真实健康数据。

## 2. 演示预检

- 公网首页、API health、数据库和模型均可用；
- 新建匿名窗口可走完主流程；
- 主模型配额和备用 provider 已验证；
- 三个原始 PDF 和知识哈希与 release 一致；
- 预置问题不依赖浏览器缓存；
- 桌面与手机视口没有遮挡、横向滚动和断字；
- 引用展开能定位文档、章节和页码；
- 故障时有本地 Compose、录屏和静态报告三重备用；
- 屏幕录制不展示 `.env`、控制台 Secret、邮箱或私人通知。

## 5. 最终回归场景

提交前至少从零执行以下 10 条：A 基础事实、B 减脂方案、B 稳糖替换、C 套餐、A/B/C 混合问、无答案拒答、过敏多轮、疾病限制、会话恢复、跨用户越权。记录期望、实际、时间、环境、commit 和截图。任何 P0 失败都回滚至上一候选版，而不是现场热修未测试版本。

## 6. 评委问答要点

- 为什么不直接让模型回答：需要可追溯、可更新且避免营养数字幻觉。
- 如何保证 C 不污染推荐：后端路由后执行 `source_role` 硬过滤，另有串库回归集。
- 如何个性化：用户约束进入确定性候选过滤，模型只负责基于证据解释和组织语言。
- 如何处理高风险用户：规则先分级，限制个体处方，提供资料范围内的一般信息和专业提示。
- 为什么选择精确检索：语料小且稳定，精确检索便于验证；只有质量/延迟证据支持时才上近似索引。
- 如何证明不是演示壳：公开 API Schema、检索 trace、测试报告、持久化历史和可复现 Compose。
