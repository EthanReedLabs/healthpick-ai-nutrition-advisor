## 2. 六分钟演示顺序

1. 打开公网首页，说明目标用户、真实百炼模型、Keyword 检索和来源透明度。
2. 依次输入“我想减重”“我在健身”“我血糖有点高”，展示三类诉求识别和 A/B 引用。
3. 编辑档案，选择减脂、45–64 岁并填写 45 岁，生成轻盈减脂主方案；展示推荐原因、行动、替换和 A/B 页码。
4. 增加海鲜过敏或高血压，证明不适宜食材硬过滤、个体化目标受限和专业提示。
5. 询问会员/企业合作，再演示混合问题，证明平台内容来自 C、营养内容不被 C 污染。
6. 展示多轮追问、历史恢复、账号搜索/删除，以及手机视口。
7. 演示空输入、超长输入、停止生成和异常提示；不要在正式演示中破坏生产容器。
8. 打开透明度和测试摘要，最后展示公网 URL、本地 Compose 和 7 天在线承诺。

现场只使用合成健康档案和临时测试账号，不展示真实邮箱、健康数据、`.env`、百炼 Key、数据库密码或服务器管理界面。演示结束删除合成对话/账号。

## 4. 最终问答要点

- 为什么不是硬编码：回答调用真实 `qwen3.7-plus`，页面显示实际模型；确定性部分只负责安全、来源、候选规则和证据校验，不预置自然语言答案。
- 如何保证 C 不污染推荐：路由先生成允许来源，检索前过滤；推荐服务只加载 A/B 规则；串库攻击回归验证。
- 为什么不用向量检索：三份语料规模小，关键词评分和受控提示更易验证数字、章节和来源；Embedding 当前禁用并如实披露。
- 如何处理疾病：不诊断、不治疗、不调药；高风险先阻断个体化目标，再给一般信息和“请咨询专业医师或注册营养师”提示。
- 如何证明可运行：公网 HTTPS、健康检查、真实模型元数据、PostgreSQL 历史、Docker Compose、镜像哈希和全量测试均有证据。
