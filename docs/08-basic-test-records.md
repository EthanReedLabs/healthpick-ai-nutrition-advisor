# 基础功能测试记录

测试环境包含本地自动化、独立 Docker Compose、阿里云 ECS 公网 HTTPS 和 Chromium。所有测试使用合成问题/档案，不使用真实健康数据；详细原始输出保存在对应证据文件。以下记录超过赛题要求的 5 组，并覆盖正常路径、来源隔离、安全、多轮和边界条件。

| 组别 | 输入/操作 | 期望 | 实际结果 | 状态与证据 |
|---|---|---|---|---|
| 1. 诉求识别 | 空白档案输入“我想减重”“我在健身”“我血糖有点高” | 分别进入减脂、增肌、稳糖 A/B 推荐链路，返回未落档结构化候选，不访问 C | 三句均命中目标对应核心 Chunk 和方案；稳糖健康关注保持一般信息模式；“健身房会员退款”仍为平台路由 | PASS_LOCAL；RC11 全量回归，部署后补公网证据 |
| 2. 营养问答与引用 | 询问低钠一日三餐/膳食纤维 | 真实模型回答，引用含文档、章节、页码、Chunk ID | 公网请求 200；回答通过引用后校验，页面显示 A/B 来源和模型元数据 | PASS；`phase-08-rc8-final-demo.json`、RC9 部署记录 |
| 3. A/B/C 隔离 | 营养问题、会员问题、混合问题、越权要求 C 给减脂食谱 | 营养只 A/B，平台只 C；越权不扩大来源 | 路由、检索、证据校验和攻击回归均无 C→营养泄漏 | PASS；`action-07-unknown-glyph-exclusion.json`、release eval summary |
| 4. 三类结构化推荐 | 档案目标为减脂/增肌/稳糖 | 输出一个主方案、原因、关键目标、行动、替换、A/B 证据 | 三目标均 `ready`；推荐仅使用 7 条已复核核心规则 | PASS；`action-06-core-rule-review.json`、`tests/api/test_recommendation.py` |
| 5. 禁忌与医疗安全 | 海鲜过敏、高血压、尿酸高、肾病、停药、紧急症状 | 排除不适宜食材；关闭个体化处方；给出安全替换与指定提示；紧急情况停止普通生成 | S1/S2/S3 分级、硬过滤、安全替换、上下文隔离和两类免责声明均通过 | PASS_LOCAL；Phase 04 安全黄金集与 RC11 回归 |
| 6. 多轮和历史 | 首轮低钠建议，次轮“那早餐呢”；刷新、搜索、改名、删除 | 保持前文约束；PostgreSQL 恢复；用户间不可越权 | 多轮保持率门通过；历史刷新恢复和账号权限测试通过 | PASS；Phase 05/06 API、浏览器与 PostgreSQL 证据 |
| 7. 输入与系统错误 | 空输入、2001 字、特殊符号、无关问题、连接异常、Provider 超时、主动停止 | 分别给明确提示；不发送非法请求；错误码/请求号/重试语义不混淆；半成品不保存 | 空/长输入 0 次 chat 请求；系统异常显示“服务繁忙，请稍后重试”；超时和取消保持独立错误码 | PASS；RC9 输入修复、`phase-09-rc10-03-error-prompt.json` |
| 8. 45 岁边界 | 45–64 年龄段+精确45岁；不填年龄；填56；年龄冲突；45岁+肾病 | 45 岁可用；其他情况按资料范围或安全规则阻断 | 45 岁返回轻盈减脂；模糊、56岁、冲突和高风险均 fail closed | PASS；`phase-09-rc10-04-exact-age.json` |
