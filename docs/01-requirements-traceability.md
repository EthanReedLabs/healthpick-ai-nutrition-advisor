# 需求—功能—测试—证据追踪矩阵

## 使用规则

- `P0`：基础项或会导致封顶/违规的要求；
- `P1`：明确进阶项；
- `P2`：差异化增强；
- 状态只镜像 `control/project-control.yaml` 的中心任务状态，不在本表独立维护第二套真值；
- 每个 `PASS` 必须有自动测试或可复核证据，不能只凭开发者口头确认。

## 当前实测快照

截至 2026-08-23 08:59，原控制面 Phase 01～08、补充赛题收口 RC10 均已通过；公网 RC10 版本保持 HTTPS 可访问、真实百炼 `qwen3.7-plus`、PostgreSQL 历史和 A/B/C 来源隔离。RC11 针对最终复核发现的三项高风险解释缺口完成本地修复：自然诉求直接生成未落档的结构化候选、尿酸/血压/家族病史自然别名、禁忌场景的通用安全替换与赛题指定方案提示语。

RC11 当前已通过 Python 全量测试、Web 全量测试、Ruff、ESLint、TypeScript、OpenAPI 类型生成和 Next production build；本地实现状态为 `PASS_LOCAL`。在 RC11 提交、镜像部署和公网复验完成前，不能把这些新增能力写成公网已上线。仍需参赛者亲自完成的外部事项是开放评委源码访问、提交比赛表单、记录真实提交时间并保持服务至少七天。

## 完成定义

一个需求只能标记为 `PASS`，当且仅当：

1. 功能已在目标环境运行；
2. 对应测试已通过；
3. 证据文件或 URL 已记录；
4. 不违反知识隔离和安全要求；
5. 提交演示脚本中能在 60 秒内展示或解释。
