## 安全设计

- 单轮语言识别只形成候选，不静默写入健康档案。
- 同一句出现多个互相冲突目标时不生成结构化候选，交给对话澄清。
- S1/S2 保持 `allow_personalized_targets=false`；新增的是没有精确热量/营养素处方的通用安全替换，不把阻断改成医疗推荐。
- S3、调药、极端减重和高风险精确处方仍在检索与模型生成前停止，不生成候选。
- 方案事实和证据只从已完成第二人复核的 A/B 规则读取；C 不进入推荐服务。

## 本轮问题与解决

1. 受控证据提示加分低于普通关键词累计分，导致“家族病史”免责声明片段未排首位。将人工核验提示权重从 25 提高到 50，并用全部主证据排序测试复验。
2. 首版新增“痛风/高尿酸”禁忌路由改变了冻结黄金集的既有内部路由。撤回这两个不必要的路由变化，仅保留赛题缺失的“尿酸高/尿酸偏高”；安全识别和高嘌呤过滤不变。
3. 全仓 Ruff format 仍会机械改动三个本轮无关历史测试文件。继续遵守工作区保护规则，只校验并格式化本轮六个 Python 变更文件；全仓 Ruff lint 已通过。
4. Docker Hub 元数据请求连续发生 TLS handshake timeout，全量 Dockerfile 构建无法开始。确认本轮未改依赖文件后，从已验收的 RC10 `linux/amd64` 镜像增量覆盖当前 API 源码和本地生产 Web standalone 产物；镜像健康与功能 smoke 通过，未改全局 Docker/网络配置。
5. 首次 API 镜像 smoke 使用了项目不存在的 `stub/memory` 枚举值，Pydantic 按设计拒绝启动。改用合法的 `mock/ephemeral` 后通过，证明不是镜像代码故障。
