# Phase 11：发送后即时反馈修复

## 目标

修复用户发送问题后，问题仍停留在输入框、对话区没有立即显示、鼠标悬停呈持续等待光标的问题；同时保持“只有完整通过证据与安全门禁的回答才写入历史”的既有约束。

## 实施计划

1. 用未完成的聊天请求稳定复现旧行为，并先建立失败回归测试。
2. 将“正在提交的问题”与已持久化对话轮次分离：发送时立即清空输入框并显示临时用户气泡。
3. 成功时用正式对话轮次替换临时气泡；失败或用户停止时移除临时气泡并恢复原输入，确保可重试。
4. 将禁用输入框的等待光标改为普通光标，避免产生页面卡死的错觉。
5. 执行组件回归、Web 全量测试、ESLint、TypeScript 与 Next.js 生产构建，记录发现的问题和验收结论。

## 验收标准

- 聊天请求尚未完成时，对话区已显示本次用户问题。
- 发送后输入框立即清空，等待期间不再显示旋转等待光标。
- 完整回答返回后只保留一份正式问答，不产生重复用户消息。
- 请求失败或停止生成后，原问题恢复到输入框，既有重试与取消语义不回退。
- Web 全量测试、静态检查、类型检查和生产构建全部通过。
