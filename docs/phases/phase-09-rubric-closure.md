# Phase 09：补充赛题说明收口执行计划

## 1. 目标与边界

本阶段针对 2026-08-23 收到的补充赛题说明做差距收口，目标是在不破坏已通过的知识隔离、医疗安全、多轮会话、账号历史与公网部署能力的前提下，关闭会影响基础需求通过线或进阶得分的明确问题，并形成逐任务记录和最终总纲验收。

本阶段不引入素材外营养事实，不允许素材 C 参与营养问答或推荐，不降低未成年人、高风险疾病、过敏和禁忌拦截，不把不同故障的内部错误码、请求编号或重试策略合并成一个不可诊断的错误，也不改动 DNS、域名备案、服务器系统服务或数据库/Caddy 容器。

## 3. 关键设计约束

### 3.1 诉求识别

只增加与三类明确业务诉求直接等价的短语，不使用“健身”“血糖”等单字宽泛命中来吞并无关问答。推荐目标必须继续来自素材 A/B 的已复核规则，平台白皮书 C 只服务平台问题。

### 3.2 异常提示

赛题指定文案作为系统异常的用户可见主提示；内部仍保留 `error.code`、`request_id`、`retryable`、日志和不同恢复动作。输入校验、客户端超时、服务端模型超时和用户主动取消不归并为系统异常。

### 3.3 年龄边界

结构化档案增加可选精确年龄。只有精确年龄与年龄段一致、位于素材规则允许区间且其他安全字段齐全时才可进入推荐。45 岁是目标人群边界；仅选择宽泛的 45–64 年龄段而没有精确年龄时继续请求补充，不推断用户一定符合规则。

### 3.4 发布与回滚

发布标签为 `rc10-rubric-closure-20260823`。服务器只接收镜像归档，不上传源码；只重建 API/Web，PostgreSQL 与 Caddy 保持原镜像、卷和运行状态。保留现有 RC9 API/Web 镜像作为回滚点。自定义域名因未提供已备案可用域名而列为条件性未实施项，不阻断公网 IP HTTPS 基础交付。

## 4. 最终总纲验收

最终核验必须覆盖：补充说明逐条追踪、全部 RC10 任务记录、开放问题为零、A/B/C 隔离、医疗免责声明、三类推荐、来源引用、多轮记忆、账号历史、输入边界、系统异常、45 岁边界、真实百炼调用、HTTPS 公网访问、7 天可用性承诺、远端代码一致性以及部署后测试数据清理。任何一项没有客观证据时不得把 Phase 09 或 FINAL-11 标记为通过。
