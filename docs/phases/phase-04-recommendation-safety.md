## 4. P04-01：健康档案与约束模型

交付范围：

- 最小化结构化字段：年龄段、性别、身高、体重、活动水平、目标、饮食偏好、不喜欢食材、过敏和医疗安全标签；
- 不接收自由文本疾病详情，不采集姓名、证件、精确住址等无关信息；
- 明确的枚举、数值范围、去重和输入长度限制；
- BMI 只在身高体重齐全时计算，返回公式、输入值和“系统估算”标记；
- Chat 请求携带档案快照，UI 可查看和编辑，服务端再次校验；
- 档案本阶段保持匿名会话级，数据库持久化属于 Phase 05。

验收矩阵：

| 层级 | 必测内容 |
|---|---|
| 单元 | 合法档案、非法枚举、身高体重边界、列表去重、BMI 公式 |
| 边界 | 空档案、仅目标、仅禁忌、未成年人、极端身高体重、超长列表 |
| API | OpenAPI 类型、Chat profile_patch 前后端一致、非法输入统一 422 |
| Web | 编辑/保存/取消、键盘可达、移动/桌面无溢出、发送请求携带当前档案 |

## 5. P04-02：确定性推荐候选与解释

- 只从经允许的 B 方案和 A/B 食材事实形成候选；
- 规则引擎先按目标和约束评分，LLM 只组织已选候选的解释；
- 返回一个主方案，最多一个备选；
- 每个候选包含匹配原因、关键目标、三步行动、替换建议和引用；
- 任何未复核或缺字符号记录不得进入候选池。

## 6. P04-03：禁忌硬过滤与风险分级

- S0：普通健康饮食问题；
- S1：过敏、不耐受、痛风、麸质等需要硬过滤；
- S2：糖尿病、肾病、心血管疾病、孕哺期、未成年人、进食障碍史；
- S3：胸痛、晕厥、呼吸困难、严重低血糖或严重过敏等紧急表现；
- 安全判定在模型调用前执行；S2 禁止精确处方，S3 直接确定性中止普通问答；
- 药物调整、诊断、疗效承诺由规则直接禁止，不交给模型自行决定。

## 7. P04-04：输出校验、拒答与免责声明

- 引用格式和来源边界继续 fail-closed；
- 校验失败最多受限重生成一次，仍失败返回安全降级，不展示原始不合规回答；
- S2/S3 检查个体化处方、药物调整、诊断和绝对化疗效词；
- 专业/紧急提示必须出现在答案主体附近；
- 日志只记录 request ID、规则 ID、错误码和回答摘要哈希，不记录完整健康档案。

## 8. P04-05：方案卡片与安全提示 UI

- 健康档案编辑器、风险级别、受限原因、免责声明和下一步建议可见；
- 颜色不是唯一提示，所有控件有可访问名称和键盘焦点；
- 普通推荐、受限回答、紧急中止、证据不足和 API 错误均有独立状态；
- 375、768、1440 三档运行态截图验收。

## 9. P04-06：安全黄金集

最低覆盖：

- 6 类过敏/禁忌，每类至少 2 条；
- 糖尿病、肾病、痛风、高血压、孕期和哺乳期各至少 2 条；
- 4 条极端减重/进食障碍、4 条药物调整、4 条紧急症状；
- 8 条提示注入/越权/串库；
- 普通营养、平台和混合问题作为非高风险对照组。

硬门槛：高风险召回率 100%、禁忌误推荐 0、A/B/C 串库 0、所有失败均有明确错误分类。
