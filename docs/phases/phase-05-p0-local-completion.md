# Phase 05 详细实施计划：P0 完整与本地部署

## 1. 阶段目标与优先级

Phase 05 把已通过的安全问答闭环补齐为可持续使用、可重复部署、可统一验收的本地 P0 产品。执行顺序按“数据正确性与丢失风险 > 接口稳定性 > 可复现部署 > 完整交互 > 总回归”排列。

| 顺序 | 任务 | 重要性 | 核心结果 |
|---|---|---|---|
| 1 | P05-01 多轮记忆与会话持久化 CRUD | 最高 | 服务端生成匿名会话/对话 ID，PostgreSQL 持久保存历史并支持读取、重命名和删除 |
| 2 | P05-02 输入边界、统一错误与超时处理 | 最高 | 非法输入、超时、依赖失败和不存在资源具有稳定、可测试、前后端一致的错误契约 |
| 3 | P05-04 Compose、迁移与 seed | 高 | 数据库从空卷可幂等初始化，知识和会话 schema 可复现，重复启动不破坏数据 |
| 4 | P05-03 三档响应式与交互状态 | 高 | 历史恢复、加载/空/错误/重试状态和 375/768/1440 三档体验完整 |
| 5 | P05-05 P0 追踪矩阵与全回归 | 门禁 | 每项 P0 要求均有实现、测试、运行证据和问题闭环 |
| 6 | P05-06 阶段退出验收 | 门禁 | 独立记录齐全、控制面通过，并确认 Phase 06 可进入 |

`P05-01`～`P05-06` 已完成，Phase 05 以 `PASS WITH ACTION` 退出并进入 Phase 06。Render 公网登录仍属于 Phase 08/ACTION-05；第二人事实复核和用户主动停止生成分别由 ACTION-06、ACTION-08 继续跟踪。

## 2. 强制工程原则

- 会话、对话和消息标识由服务端创建；前端收到数据库规范 ID 后必须替换临时状态。
- 持久化写入后返回数据库实际记录；更新或删除影响 0 行必须返回明确的不存在错误，不得静默成功。
- 匿名会话只保存完成产品功能所需的数据；日志继续禁止记录完整健康档案和完整回答。
- 迁移和 seed 必须可重复执行；现有数据不得因应用重启被清空。
- 每个任务结束立即创建 `control/records/<TASK>.yaml`，同步记录发现的问题、根因、解决方案、证据和残余行动。
- 每次任务推进后运行统一控制面审计；Phase 05 退出前再执行一次总纲查漏，但最终总纲签署仍在 P08-07。

## 3. P05-01：多轮记忆与会话持久化 CRUD

实施内容：

1. 新增匿名会话、对话和对话轮次表及索引，使用外键和级联删除保证归属与生命周期一致。
2. 新增 PostgreSQL 会话仓储，同时保留仅供自动测试/显式降级使用的内存仓储。
3. 提供匿名会话创建、对话创建/列表/详情/重命名/删除 API；所有资源访问同时校验匿名会话归属。
4. Chat 请求绑定服务端生成的匿名会话和对话 ID；成功回复持久化后返回规范轮次 ID。
5. 前端首次访问创建匿名会话，新建对话使用服务端 ID，刷新后恢复历史；删除和重命名入口的体验增强可在 P06-02 延续，但底层 CRUD 本阶段完成。
6. 覆盖并发追加、跨会话越权、0 行更新/删除、级联删除、刷新恢复和服务重启恢复测试。

验收门槛：

- 服务重启后会话历史仍可读取；
- 两个匿名会话之间不可读取或修改对方对话；
- 并发写入不丢轮、不重复，返回的轮次 ID 与数据库一致；
- 不存在资源统一返回稳定错误；
- API、Web、OpenAPI 类型和真实本地运行证据齐全。

## 4. P05-02：输入边界、统一错误与超时处理

- 冻结统一错误体：`code`、`message`、`request_id`、可选 `details`，禁止向客户端暴露堆栈、密钥或提供商原始响应。
- 限制请求体、消息、标题、列表和分页参数；格式、长度、枚举和业务冲突分别测试。
- 对模型、Embedding、数据库和 SSE 设置清晰超时与可判别错误码；可安全重试的错误由 UI 提供重试操作。
- 处理客户端中断与 SSE 半途失败，避免把未完成回答写入历史。

## 5. P05-04：Compose、迁移与 seed

- Compose 健康检查覆盖 PostgreSQL/pgvector、API 和 Web 的真实依赖顺序。
- 迁移按版本顺序执行并记录，支持空库初始化和已有库增量升级。
- seed 导入 A/B/C 已验证知识，保持 C 来源隔离；重复执行结果计数稳定。
- 执行“空环境启动 → smoke → 重启 → 再 smoke → 数据保留”验收。

## 6. P05-03：三档响应式与交互状态

- 会话列表、当前会话、历史消息和引用可在刷新后恢复。
- 空状态、初始化加载、发送中、流式回答、失败、超时、重试和删除后的选择状态独立呈现。
- 375、768、1440 三档无横向溢出，移动端保留新对话、历史和健康档案入口。
- 关键控件具备可访问名称、焦点状态和键盘操作；颜色不是唯一状态提示。

## 7. P05-05：P0 追踪矩阵与全回归

- 更新赛题需求追踪矩阵，逐项关联需求、代码、自动测试、运行证据和任务记录。
- 执行 Python 全测、Ruff、Web 单测、Lint、类型检查、生产构建、数据库 smoke、真实模型 smoke 和三视口浏览器验收。
- 复核所有 Phase 01～05 的开放问题与行动；不能关闭的项目必须说明是否阻断最终验收。

## 8. P05-06：退出验收

只有以下条件同时满足才允许关闭 Phase 05：

- P05-01～P05-05 均有独立完成记录且达到各自验收门槛；
- 本地从空数据库可复现启动，重启后会话和知识数据保持；
- P0 追踪矩阵无未解释空项，全量质量门为绿；
- `scripts/control_plane.py` 结构审计为 `PASS`；
- 阶段问题均已解决，或绑定了明确 owner、截止点、影响和行动；
- 形成 `docs/evidence/phase-05-baseline-record.md`，并在统一控制面明确 Phase 06 的进入条件。
